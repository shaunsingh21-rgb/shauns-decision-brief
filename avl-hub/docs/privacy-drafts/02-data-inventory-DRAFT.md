# AVL Tech Hub — personal data inventory (DRAFT)

> **DRAFT for the institution's own counsel / privacy office / IT security office to review. Not legal advice.** Prepared from the schema (`migrations/001`–`007`), the server code and live tests on a throwaway server (2026-11-21). "Proven" = I created data and observed it; "Read" = from code only. Retention-today facts are what the code does now.

Roles below: **Admin** = Leader/Admin; **Audit** = holder of `audit.view`; **Manage** = `users.manage`; **Data** = `data.manage`; **Trainer** = `training.score/signoff` + `progress.view_all`; **Anyone** = every signed-in user (including Viewer).

## C. What is inside `audit_log.detail` (proven on 15 actions)
* `auth.login`: `{}`; `actor_name` = username, `ip` = client IP.
* `auth.login_failed` / `auth.lockout`: `{"username": "<whatever was typed>"}` and `actor_name` = the same. **Proven: typing a password into the username box stored that password in the log in clear (twice: `actor_name` and `detail`)**, readable by every Audit holder, forever.
* `practical.score`: trainee **display name**, trainee id, skill, score. `signoff.create`: trainee display name, id, module, version, quiz %, scores, and the **free-text note** (proven: a medical remark typed as a note is in the audit log).
* `research.search`: the **query text**. `user.create`: username, role. `user.update`: before/after. `file.upload`: mime/size only (no file name).
* Offline changes add `occurred_at`.

## D. "Who can see whom" judgement
* `/api/people` (all signed-in users): id, **display name**, role name, can-train flag. No username, no last sign-in, no disabled people. **Acceptable and needed** (trainee pickers); a Viewer sees the whole team list with roles. Suggest limiting Viewer to names only and confirming this is acceptable for any non-employee viewers.
* `/api/skill-matrix`: others' scores only with `progress.view_all` (proven: Technician sees own row; Viewer sees nobody).
* `/api/progress/:id`: another person's record only with `progress.view_all` (proven: the Technician could read their own id; the Viewer got 403 for the Technician's id; the Trainer, who holds the permission by default, got 200).
* `issues.created_by` / `updated_by` ids are exposed to everyone but names are not in the payload; still, ids can be joined to `/people` by any user, so **authorship of every issue is effectively public inside the app** (by design, DECISIONS §29).
* Audit log: Audit/Admin only, includes IPs and typed usernames.
